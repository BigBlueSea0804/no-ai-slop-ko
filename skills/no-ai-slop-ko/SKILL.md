# 한국어 No AI Slop

한국어 글을 날카롭게 다듬되 작성자의 주장과 목소리를 유지한다. AI 문체를 제거한다는 이유로 모든 문장을 반듯하고 무난하게 만들지 않는다.

## 작업 모드

### 편집

기본 모드로 사용한다. 필요한 부분만 수정하고 다음을 반환한다.

1. 수정한 전체 글
2. 짧은 **수정한 내용**

사용자가 편집 강도를 지정하면 따른다.

- **최소 편집:** 명백한 AI 표현, 오류, 중복만 수정한다.
- **기본 편집:** AI 표현과 번역투를 줄이고 흐름을 개선한다.
- **적극 편집:** 주장과 말투를 보존하면서 문단 구조와 순서까지 조정한다.

강도 지정이 없으면 기본 편집을 적용한다.

### 검사

사용자가 검사, 진단, 감사, 탐지 또는 "AI처럼 보이는 표현만 찾아 달라"고 요청하면 글을 다시 쓰지 않는다. 발견한 항목마다 다음을 반환한다.

- 패턴 이름
- 문제가 드러나는 짧은 원문 인용
- 문제가 되는 이유
- 간단한 수정 방향

AI가 작성했는지 추측하거나 확률과 점수를 제시하지 않는다. 이름 붙일 수 있는 문체 패턴만 근거로 제시하고, 마지막에 편집을 원하는지 묻는다.

## 필요한 정보

초안이 없으면 붙여 넣어 달라고 요청한다.

독자나 게시 위치가 불분명하고 결과에 영향을 준다면 한 가지만 묻는다. "누가 어디에서 읽을 글인가요?"

글의 목적이 불분명하면 독자가 읽은 뒤 무엇을 생각하거나 느끼거나 행동해야 하는지 묻는다.

질문 없이도 안전하게 편집할 수 있으면 작업을 진행한다.

## 편집 원칙

- **주장과 사실을 보존한다.** 사용자가 주지 않은 주장, 수치, 사례, 인용, 출처, 감상 또는 의견을 만들지 않는다. 자연스러운 연결이나 결론을 만든다는 이유로 작성자의 반응을 추측하지 않는다.
- **말투를 보존한다.** 단어 선택, 문장 길이, 리듬, 직설성, 유머, 망설임, 여담과 완성도를 먼저 파악한다.
- **높임말 수준을 보존한다.** `합니다체`, `해요체`, 평서체와 반말을 임의로 바꾸지 않는다. 혼용이 의도인지 불분명하면 확인한다.
- **매체에 맞춘다.** 블로그, 보고서, 이메일, SNS, 발표문에 같은 문체를 강요하지 않는다.
- **최소한으로 고친다.** 강한 문장과 자연스러운 사람의 표현은 그대로 둔다. 모든 문단을 같은 모양으로 정리하지 않는다.
- **구체적인 정보를 지킨다.** 이름, 수치, 날짜, 작동 방식과 사례를 추상적인 평가로 바꾸지 않는다.
- **결론을 먼저 쓸 때만 이득이 있으면 앞세운다.** 개인적인 경험이나 긴장을 만드는 도입은 보존한다.
- **한국어 어순을 우선한다.** 영어 문장 구조를 옮긴 번역투를 자연스러운 한국어로 바꾼다.
- **동사가 일하게 한다.** `개선을 진행했다`보다 `개선했다`처럼 불필요한 명사화를 줄인다.
- **문장 호흡을 보존한다.** 이해하기 어려운 문장만 풀어 쓴다. 분명한 짧은 문장, 생략, 구어체와 리듬 변화는 살린다.
- **독자에게 감상을 지시하지 않는다.** 중요하고 놀랍다는 설명 대신 사실과 결과가 의미를 보여주게 한다.
- **삭제한 결론을 새 감상으로 대체하지 않는다.** 근거 없는 결론을 삭제한 뒤에는 원문에 이미 있는 마지막 구체적인 사실, 판단 또는 행동에서 끝낸다.
- **출처를 꾸미지 않는다.** `전문가들은`, `연구에 따르면`처럼 출처가 불분명한 주장은 출처를 요청하거나 삭제한다.
- **구조는 문제가 있을 때만 바꾼다.** 문단 순서를 변경했다면 **수정한 내용**에서 이유를 알린다.

## 한국어 패턴 적용

편집 또는 검사 전에 [`references/korean-patterns.md`](references/korean-patterns.md)를 읽고 글에 실제로 나타난 패턴만 적용한다.

패턴 목록을 기계적인 금칙어 사전처럼 적용하지 않는다. 인용문, 고유명사, 기술 용어, 의도적인 반복과 실제 근거가 있는 표현은 유지한다.

## 기본 작업 절차

1. 초안 전체를 먼저 읽는다.
2. 글의 목적, 핵심 주장, 독자와 게시 위치를 파악한다.
3. 보존할 목소리의 특징을 적어도 세 가지 확인한다. 예: 높임말 수준, 문장 호흡, 직설성, 유머, 여담.
4. 검사 요청이면 한국어 패턴을 이름 붙여 보고하고 작업을 끝낸다.
5. 편집 요청이면 실제 문제가 있는 부분만 수정한다.
6. [`eval.md`](eval.md)의 모든 항목으로 결과를 자체 검수한다.
7. 실패한 항목이 있으면 수정하고 다시 검수한다.
8. 전체 수정본과 짧은 **수정한 내용**을 반환한다.

## 출력 형식

### 편집 모드

수정한 전체 글을 먼저 제시한다. 이어서 다음과 같이 간단히 설명한다.

```markdown
**수정한 내용**

- 상투적인 도입 표현 삭제
- 번역투를 자연스러운 한국어 어순으로 수정
- 원문의 해요체와 개인적인 예시는 유지
```

수정 사항이 거의 없으면 억지로 목록을 늘리지 않는다.

### 검사 모드

```markdown
1. **근거 없는 해설**
   - 원문: "이는 시장에서 좋은 반응을 얻고 있음을 보여줍니다."
   - 이유: 앞의 수치를 근거 없이 긍정적으로 해석함
   - 방향: 해설을 삭제하거나 실제 사용자 반응 자료를 제시
```

발견한 패턴이 없으면 없다고 분명히 말하고 자연스러운 문장을 문제 삼지 않는다.
